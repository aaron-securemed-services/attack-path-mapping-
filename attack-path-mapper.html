Assessment guide

How to turn lab work into a defensible attack-path assessment.

Workflow

  1. Scope it. With nothing selected, the Details tab holds the assessment record: target, assessor, date, scope and rules of engagement.
  2. Map entry vectors. Every interface an attacker could reach: network services, wireless, USB / serial / debug ports, update mechanisms, cloud or mobile companions.
  3. Record findings as you test. One node per weakness. Start as suspected; move to confirmed or exploited once you have evidence. Paste the command and output you used into Evidence so someone else can reproduce it.
  4. Link what each finding gives you. A finding leads to a capability (shell, credentials, ability to modify data). Capabilities chain into further findings or into a consequence.
  5. Rate it. Give each finding a severity (the CVSS v3.1 calculator can set it) and an ease of exploitation (1–5). Give each consequence an impact (1–5). Paths are then ranked automatically.
  6. Test mitigations. Tick Mitigated on a node to see which paths break. The Analysis tab ranks the nodes whose removal protects the most.
  7. Review, then report. The Review tab lists gaps (missing evidence, unrated findings, dead ends). Publish Report builds a print-ready document.

How the numbers work

  • Path risk = exploitability × impact (1–25). Exploitability is the hardest rated finding on the path — an attacker must get past every step. Impact is the rating of the consequence at the end. 15+ critical · 10+ high · 5+ medium · below 5 low.
  • OR / AND. By default a node is reached if any incoming path works (OR). Set Requires: all incoming (AND) when the attacker needs several things at once — e.g. a modified firmware image and a device that skips signature checks.
  • Choke point — a node whose removal makes at least one consequence unreachable. These are the highest-value places for a control.
  • A finding marked ruled out is treated as not exploitable and breaks the paths through it.
